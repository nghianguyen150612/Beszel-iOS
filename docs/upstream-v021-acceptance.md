# v0.21 iOS acceptance plan

This plan defines evidence required after integration. P003 does not build the
upgraded Agent or Hub and does not test a new upstream binary on an iPad. Cases
marked **planned** are not passes. The historical 0.19 record is shown
separately and cannot satisfy a 0.21 gate.

## Reference device and evidence rules

Physical reference: iPad mini 2, A1489 / iPad4,4, Apple A7, iOS 12.5.7,
Amethyst / Procursus. Preserve the existing `/var/lib/beszel-hub` directory;
never use it for migration tests. Capture command output, binary checksums,
version/build metadata, relevant service logs, and timestamped before/after
invariants. Redact tokens and private key material. Tests that use a database
must use synthetic disposable data.

## Phase gates

| Gate | Measurable acceptance |
| --- | --- |
| A — P003 readiness | All 178 upstream commits and 13 logical iOS patches have canonical owners; all 21 P0 SHAs map to explicit controls; compatibility scenarios, migration/backup plan, acceptance evidence, risks, owners, and blockers are recorded; no critical security/data-loss risk lacks a mitigation and blocking gate. This gate approves readiness documentation only. |
| B — P004–P006 history | Required upstream history is integrated; all iOS patches survive; schema and iOS behavior diffs are reviewed; merge conflicts have named decisions; no production deployment occurs. |
| C — P007–P012 platform and Agent | Agent and Hub build for iOS/arm64 with CGO and iOS 12 metadata; A7 runtime constraints remain; Agent metrics/networking pass; unsupported collectors are absent/no-op; remote platform behavior does not regress. |
| D — P013–P015 Hub and frontend | Security/authorization and migration tests pass; existing records survive disposable upgrade; API/frontend contracts agree; embedded frontend build succeeds; dependency findings are triaged. |
| E — P016–P017 installer and candidate | Installer/CLI, CI, checksums, backup/restore, and reproducible candidate tests pass; release-candidate artifacts are recorded; no release is published. |
| F — P018 device and release authorization | Real-device A7 tests pass; migration and restore are demonstrated safely on disposable data; services recover after reboot/reactivation; explicit release approval is recorded. |

## Blocking policy

Unknown migration outcome, unverified backup/restore, authorization failure,
missing A7 runtime evidence, or an unmitigated critical risk blocks the
corresponding gate. Feature feasibility questions such as native iOS Wi-Fi RSSI
may remain deferred only with an owner and a defined absent/no-op fallback.
P004 may begin only after Gate A is structurally complete; no production upgrade
is authorized by that decision.

## P012 owner-approved deferral — 2026-10-16

The owner-approved decision in [PR #14](https://github.com/nghianguyen150612/Beszel-iOS/pull/14#issuecomment-6206076758)

accepts P012's safe unavailable/nil fallback, source checks, and documented cloud
CI for integration and authorizes P013 after normal finalization of PR #14. This
is not evidence that RSSI was measured or that native acquisition works. P018
owns physical validation; P016 owns any future evidence-backed signing,
entitlement, or helper packaging changes. The P012 physical/device portion of
Gate C remains pending P018, and no release is authorized by this decision.
