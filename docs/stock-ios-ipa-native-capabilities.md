# Stock iOS native metric capabilities

Target for future validation is iPhone 13 (`iPhone14,5`), A15, stock iOS 27.0.1 and a correctly provisioned IPA. Physical-device validation remains **DEFERRED — OWNER APPROVED**. The implementation targets the public iPhoneOS SDK and iOS 16.0 deployment. The host test binaries exercise injected readings and Security calls. Stock sandbox access is a separate runtime question.

## Public APIs and scopes

| Local diagnostics | Public interface | Semantics and availability |
| --- | --- | --- |
| CPU ticks and busy percent | `mach_host_self`, `host_processor_info(PROCESSOR_CPU_LOAD_INFO)`, `sysconf(_SC_CLK_TCK)` | Per-logical-processor cumulative 32-bit user, system, nice and idle ticks. Consecutive reads may yield a system-wide percentage after validation. The A15's stock sandbox and timing behavior are unverified |
| Logical processors | `ProcessInfo.processorCount`, `activeProcessorCount` | OS-reported logical counts. The Mach sample separately reports its enumeration size. No assertion about physical cores, threads per core or performance/efficiency core assignment |
| Physical memory | `ProcessInfo.physicalMemory` | Device bytes. A nonzero total is required to interpret VM counts |
| Host VM free, Darwin available and Darwin used memory | `host_page_size`, `host_statistics64(HOST_VM_INFO64)` | Returned values depend on Mach access and validity. Free excludes speculative pages. The two Darwin values use the definition below. This is a local system VM diagnostic, with stock sandbox behavior unverified |
| Battery level and state | `UIDevice.isBatteryMonitoringEnabled`, `batteryLevel`, `batteryState` | Device percent and UIKit state. A level of 0 is valid. UIKit -1 or out-of-range level and unknown state are independent unavailable results |
| Volume capacity and available for important usage | `URL.resourceValues` for the app's Application Support/Agent directory | Reported volume bytes and the estimate of bytes available for important writes from that app URL. The estimate may include purgeable space and special APFS capacity semantics. Neither estimate is whole-device used storage or a measurement of bytes owned by the app. Disk space diagnostics are local under reason 85F4.1 |
| Device identity | Public `uname`, `UIDevice.name`, `systemVersion`, Go runtime arch | `uname.machine` is the model identifier. UIKit can return a generic name. These values are separate from the stable random installation fingerprint. No user-assigned-name entitlement is requested |

API references for [Foundation ProcessInfo](https://developer.apple.com/documentation/foundation/processinfo), [UIKit battery level](https://developer.apple.com/documentation/uikit/uidevice/batterylevel), [important-usage capacity](https://developer.apple.com/documentation/foundation/urlresourcekey/volumeavailablecapacityforimportantusagekey), and [required-reason APIs](https://developer.apple.com/documentation/bundleresources/app-privacy-configuration/nsprivacyaccessedapitypes/nsprivacyaccessedapitype).

The Mach CPU probe uses the public host port and processor-info flavor. It tests the return code, validates the returned shape, copies only the expected number of ticks and releases the returned out-of-line VM and its host send right. The VM probe validates the returned statistics revision and releases the host send right. Permission failures, unsupported operations and other Mach errors become unavailable readings. Kernel interfaces can return failures or restricted/cached data in actual platform configurations. An SDK build or open XNU source cannot establish what the stock iPhone sandbox will return. [XNU processor tick implementation](https://github.com/apple-oss-distributions/xnu/blob/f6217f891ac0bb64f3d375211650a4c1ff8ca1ea/osfmk/kern/processor.c), [host statistics implementation](https://github.com/apple-oss-distributions/xnu/blob/f6217f891ac0bb64f3d375211650a4c1ff8ca1ea/osfmk/kern/host.c), [VM-statistics field definitions](https://github.com/apple-oss-distributions/xnu/blob/f6217f891ac0bb64f3d375211650a4c1ff8ca1ea/osfmk/mach/vm_statistics.h).

## CPU sampling

`StockMetrics` is isolated to the Swift main actor. This serializes polling and foreground reset. The foreground timer requests samples every 2 seconds. Interval validation uses a monotonic `ContinuousClock` with a 0.5–6 second accepted interval. On leaving the active scene, the CPU baseline is cleared. A first sample, an inaccessible API, or a changed reported processor count or active processor count cannot yield busy percent. A long gap or processor-count change starts a new baseline. The probe can still report the raw counts when utilization is unavailable. Going inactive also preserves the existing Agent Stop behavior.

The accumulator uses unsigned modulo 2³² per counter and rejects a per-processor aggregate delta above twice elapsed seconds × clock ticks per second plus eight ticks. This tolerates tick quantization and traversal time while rejecting implausible jumps, including ordinary backward counter jumps. Invalid or zero aggregate deltas cannot yield a zero percentage. For valid intervals, busy percent is 100 × Δ(user + system + nice) / Δ(all), with sums over reported processors and therefore bounded to 0–100 inclusive. No process CPU counters or assumed A15 core count are used. The actual measured interval is available in seconds when a utilization sample is accepted. A same-count topology replacement or reset close to wrap can be indistinguishable from a normal modulo increment. Device runs should compare successive foreground readings and timing with independently observed OS behavior before qualifying the metric for Hub use.

## Memory sampling

The pinned gopsutil Darwin collector uses `available = pageSize × (free_count + inactive_count)` and `used = physicalMemory - available`, using the legacy host VM statistics flavor. Open XNU fills free and inactive counts equivalently in the two flavors and includes speculative pages within `free_count`. The probe reproduces that Darwin definition with `HOST_VM_INFO64`, while the distinct `freeMemory` estimate subtracts speculative pages. This does not assert all inactive memory is immediately available, account for current app allocation headroom, or count compressed memory as reclaimable. Beszel additionally applies its [selected Agent memory policy](../agent/system.go), such as the htop option or ZFS ARC adjustments on other platforms. The stock app does not export these diagnostics as default Hub memory values. [Pinned gopsutil Darwin implementation](https://github.com/shirou/gopsutil/blob/v4.26.8/mem/mem_darwin.go).

The conversion rejects zero or misaligned physical totals, zero page size, speculative counts larger than free counts, overflowing sums/products and totals above physical memory. A tested 16 KiB page case with 10 free (2 speculative) and 20 inactive of 100 pages yields 8 strictly free, 30 Darwin-available and 70 Darwin-used pages. These diagnostics preserve bytes and distinguish a legitimate zero from a rejected reading.

## Bridge, tests and remaining device evidence

Each probe has an availability flag, scope, unit and UTC sample timestamp. A successful result has a value and a failed result has a reason. The native JSON crosses the existing C ABI into a mutex-protected Go snapshot. Original diagnostic fields remain available for existing consumers. Local diagnostics do not require an active Hub connection or access to app storage. The Agent collector continues to return the existing unavailable error, independent of probe results. See the [compatibility matrix and owner decision](stock-ios-ipa-metric-compatibility.md).

- `MetricSamplingTests.swift` covers successful native-shaped samples, permission/unsupported results, first sample, valid 0 and 100 percent, deltas, wrap, reset, processor counts, suspend-length gaps, invalid memory page counts and conversion, unknown/zero battery level and absent capacity.
- `runtime_test.go` covers native metadata consistency, integer overflow rejection, measurements missing or zero and concurrent Go updates/status reads. Swift production sampling is main-actor isolated.
- `TokenStoreTests.swift` exercises injected Security calls for missing and valid entries, in-place update, insertion and denied access. Host tests do not use a real Keychain item. Keychain accessibility/unlock behavior and stock provisioning need device evidence.
- After owner authorization for device validation, observe the first foreground sample and several subsequent samples, record availability, return codes and intervals, verify a post-inactive baseline reset, compare host VM totals and battery with independently observed data, and keep storage estimates scoped to the app. This remains separate from accepting any metrics in a Hub.
